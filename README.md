## 🧠 What is Ralph Wiggum?

Ralph Wiggum is an autonomous development technique created by **Geoffrey Huntley**. At its core, it's simple:

```bash
while :; do cat PROMPT.md | copilot; done
```

A bash loop that repeatedly feeds the same prompt to an AI agent until the task is complete.

### Philosophy

> _"The technique is **deterministically bad in an undeterministic world**."_

- When Ralph fails, you don't blame the tools — **you tune the prompts**
- Failures are predictable and informative
- Success requires faith in eventual consistency
- Each failure teaches you what "signs" (guardrails) to add

### The Playground Metaphor

From Huntley:

> _"Ralph is very good at making playgrounds, but he comes home bruised because he fell off the slide, so one then tunes Ralph by adding a sign next to the slide saying 'SLIDE DOWN, DON'T JUMP, LOOK AROUND,' and Ralph is more likely to look and see the sign."_

Eventually, the prompt has enough guardrails that Ralph works reliably.

## 🔧 How to Set Up

### Prerequisites

| Requirement | Description |
|------------|-------------|
| **GitHub Copilot CLI** | Installed and authenticated |
| **Git** | For state tracking and memory |
| **GitHub Copilot Subscription** | Pro, Pro+, Business, or Enterprise |
| **Node.js** | v22+ and npm v10+ |

### Step 1: Install GitHub Copilot CLI

If you haven't already installed GitHub Copilot CLI:

```bash
# Install via npm
npm install -g @github/copilot

# Verify installation
copilot --version

# Authenticate (follow prompts)
copilot
```

### Step 2: Clone this Repository

```bash
git clone https://github.com/RichardScottOZ/ralph-copilot.git
cd ralph-copilot
```

### Step 3: Set Up a New Project

```bash
# Copy the ralph-copilot setup to your project
./setup-ralph.sh my-project

# Or manually:
mkdir my-project
cd my-project
git init
mkdir -p .copilot/instructions
cp -r /path/to/ralph-copilot/.copilot/instructions/* .copilot/instructions/
cp /path/to/ralph-copilot/templates/* .
```

### Project Structure After Setup

```
my-project/
├── .git/                          # Git repo (required)
├── .copilot/
│   └── instructions/
│       ├── clarify-phase.md       # Phase 1: Requirements discovery
│       ├── plan-phase.md          # Phase 2: Generate execution files
│       └── execute-phase.md       # Phase 3: Execute tasks
├── PROMPT.md                      # Ralph's instructions (generated by plan)
├── TODO.md                        # Task checklist (generated by plan)
├── clarify-session.md             # Requirements (from interview)
└── src/                           # Your code (created during execution)
```

## 📋 Phase 1: Clarify

The clarify phase uses interactive questioning to gather **40-70 questions** covering all aspects of the project.

### Why This Matters

> _"The loop pressure overrides the natural tendency to stop asking after 3-5 questions."_

### Question Categories

| Category | Questions to Cover |
|----------|-------------------|
| **Core Requirements** | What must this do? What's MVP? What's out of scope? |
| **Users & Context** | Who uses this? What's their skill level? What constraints exist? |
| **Technical Choices** | Language? Framework? Database? Dependencies? |
| **Integration Points** | What systems does this connect to? What data flows in/out? |
| **Edge Cases** | What happens when things fail? Boundary conditions? |
| **Quality Attributes** | Performance requirements? Security considerations? |
| **Existing Patterns** | How do similar things work in this codebase? Conventions? |
| **Preferences** | Strong opinions on approach? Tradeoffs? |

### Running the Clarify Phase

```bash
# Start the clarify phase with GitHub Copilot CLI
copilot

# Then provide the clarify instructions by typing:
# Read .copilot/instructions/clarify-phase.md and follow its instructions to interview me about my project

# Or pipe the instructions:
cat .copilot/instructions/clarify-phase.md | copilot

# Answer the questions thoroughly
# Save results to clarify-session.md as you go
```

### Output: `clarify-session.md`

```markdown
# Discovery: Task Management API

Started: 2024-01-10

## Questions Asked
1. What authentication method? → JWT
2. What database? → PostgreSQL
3. ...

## Answers Received
- Authentication: JWT with refresh tokens
- Database: PostgreSQL with Prisma ORM
- ...

## Emerging Requirements
- Must support 1000 concurrent users
- API must be RESTful with OpenAPI spec
- All endpoints require authentication except /health
- ...
```

## 🚀 Phase 3: Execute

Run the Ralph loop until complete.

### Basic Loop

```bash
# Simple bash loop
while :; do cat PROMPT.md | copilot; done
```

### Enhanced Loop with Completion Detection

```bash
# Loop that exits when "DONE" is detected
while :; do 
  output=$(cat PROMPT.md | copilot)
  echo "$output"
  if echo "$output" | grep -q "DONE"; then
    echo "Task completed!"
    break
  fi
done
```

### Using the Provided Script

```bash
# Use the provided execution script with safety features
./ralph-execute.sh

# With custom options
./ralph-execute.sh --max-iterations 30 --completion-word COMPLETE
```

### What Happens During Execution

```
Iteration 1: Copilot reads PROMPT.md → Picks Task 1 → Implements → Commits
     ↓
Iteration 2: Copilot reads PROMPT.md → Sees Task 1 done → Picks Task 2 → Implements → Commits
     ↓
Iteration 3: ...
     ↓
Iteration N: All tasks done → Copilot outputs "DONE" → Loop exits
```

Each iteration:
- Sees the same `PROMPT.md`
- But files have changed (previous work persists)
- Git history shows progress
- `TODO.md` reflects completed tasks

## 📄 Templates

### Minimal PROMPT.md (Start Here)

```markdown
# PROMPT.md

Build [WHAT YOU'RE BUILDING].

Requirements:
- [Requirement 1]
- [Requirement 2]
- [Requirement 3]

Track progress in TODO.md. Commit after each completed item.

When all requirements are implemented and tests pass, output: DONE
```

### PROMPT.md with Guardrails

```markdown
# PROMPT.md

## Task
[Description of what to build]

## Requirements
Read clarify-session.md for full requirements.

## Instructions
1. Read TODO.md for current tasks
2. Pick highest priority incomplete task
3. Read any files before editing them
4. Implement the task
5. Run tests
6. If tests fail, fix before continuing
7. Mark complete in TODO.md
8. Commit with clear message
9. Repeat until all tasks done

## Signs (Guardrails)
- Always read before editing
- Never skip failing tests
- Don't refactor unrelated code
- Keep commits focused
- Update TODO.md immediately after completing tasks

## Completion
When TODO.md shows all tasks complete and tests pass, output: DONE
```

### TODO.md Template

```markdown
# TODO

## Critical (Must Have)
- [ ] Task 1
- [ ] Task 2
- [ ] **HARD STOP** - Verify core flow works end-to-end

## Important (Should Have)
- [ ] Task 3
- [ ] Task 4

## Nice to Have
- [ ] Task 5
- [ ] Task 6

---
## Completed
- [x] Example completed task
```

## 🔄 Differences from Kiro CLI

This implementation adapts the original Ralph Wiggum workflow from Kiro CLI to GitHub Copilot CLI:

| Feature | Kiro CLI | GitHub Copilot CLI (This Repo) |
|---------|----------|-------------------------------|
| **Plugin System** | Agent YAML files | Markdown instruction files |
| **Commands** | `kiro-cli chat --agent` | `copilot` interactive or piped |
| **Clarify Phase** | `--agent ralph-clarify` | Pipe `.copilot/instructions/clarify-phase.md` |
| **Plan Phase** | `--agent ralph-plan` | Pipe `.copilot/instructions/plan-phase.md` |
| **Execute Phase** | `--mode script` | Standard input piping |
| **Configuration** | `.kiro/agents/*.yaml` | `.copilot/instructions/*.md` |
| **Loop Control** | Manual bash loop | Manual bash loop (same) |
| **Completion Detection** | Plain text "DONE" with grep | Plain text "DONE" with grep (same) |

### Key Adaptations

1. **Markdown Instructions instead of YAML Agents**: GitHub Copilot CLI uses natural language prompts, so we provide instructions as Markdown files
2. **Interactive or Piped Input**: Use `copilot` interactively or pipe instructions with `cat file.md | copilot`
3. **Same Bash Loop Philosophy**: The execution loop works the same way
4. **Repository-Aware Context**: Copilot CLI automatically understands your repository structure and git state
5. **No Special Modes**: GitHub Copilot CLI doesn't have a "script mode" - it processes stdin naturally

## 🛠️ Troubleshooting

### Loop Runs Forever

**Problem**: The loop doesn't detect completion

**Solutions**:
- Ensure PROMPT.md explicitly tells Copilot to output "DONE"
- Check that the completion string matches exactly
- Add a max iterations limit to your loop (use `ralph-execute.sh`)

### Copilot Doesn't Follow Instructions

**Problem**: Copilot skips tasks or doesn't follow PROMPT.md

**Solutions**:
- Add more specific guardrails to PROMPT.md
- Break down large tasks into smaller, clearer subtasks
- Review completed iterations and add "signs" for common failures
- Make sure PROMPT.md is clear and unambiguous

### GitHub Copilot CLI Authentication Issues

**Problem**: CLI asks for authentication repeatedly

**Solutions**:
```bash
# Re-authenticate by starting Copilot and following prompts
copilot

# Check your GitHub Copilot subscription status
# at https://github.com/settings/copilot
```

### Copilot Not Making File Changes

**Problem**: Copilot suggests but doesn't execute changes

**Solutions**:
- Copilot CLI may need explicit permission to write files
- Review suggestions and confirm them
- Consider adjusting your prompts to be more directive

## 🎓 Philosophy Recap

Ralph Wiggum is about:

1. **Iteration**: Repeat until done, not turn-by-turn interaction
2. **Guardrails**: Add "signs" based on failures
3. **Autonomy**: Let the AI work without constant supervision
4. **Tuning**: Improve prompts, not blame tools
5. **Patience**: Trust in eventual consistency

### When to Use Ralph

✅ **Good for:**
- Large refactoring projects
- Greenfield development with clear requirements
- Test-driven development loops
- Repetitive implementation tasks

❌ **Not ideal for:**
- Exploratory/research tasks
- Complex debugging of unknown issues
- Tasks requiring frequent human judgment
- High-stakes production changes without review
